# v0.15.0 — Pronunciations, Dictionaries and Surrounding Text

This release lets callers control how names and terms are said, and sends
the pronunciation dictionary and surrounding-text settings that the
OmniVoice provider accepted but dropped.

## Highlights

- **Pronunciations through OmniVoice**: `SynthesisConfig.Pronunciations`
  gives each term's IPA and respelling. Models that honour phonemes
  (`eleven_flash_v2`, `eleven_turbo_v2`, `eleven_monolingual_v1`) get IPA as
  SSML `<phoneme>` tags; other models, including the default
  `eleven_multilingual_v2`, get the respelling
- **Dictionaries and surrounding text reach the request**: the
  `WithPronunciationDictionary`, `WithPreviousText` and `WithNextText`
  extensions are now sent

## Added

- `tts.Request` gains `PronunciationDictionaries` (up to three, each at its
  latest version unless one is given), `PreviousText` and `NextText`
- `tts.SupportsPhonemes(model)` reports whether a model honours phoneme tags
- OmniVoice provider: `SynthesisConfig.Pronunciations` is applied to
  synchronous text and to `SynthesizeStream`, which enables SSML parsing on
  the WebSocket when it sends phoneme tags; `SynthesizeFromReader` sends
  text as it arrives, without pronunciations
- OmniVoice provider: `SendsPhonemes(config)` reports whether a request's
  text carries phoneme tags
- OmniVoice provider: `WithPhonemes(config, bool)` overrides whether IPA is
  sent as phoneme tags
- OmniVoice provider: `WithPronunciationDictionaryVersion` pins a dictionary
  version
- OmniVoice provider: `DictionaryRules(pronunciations, phonemes)` turns
  pronunciations into dictionary rules: phoneme rules from IPA, alias rules
  from respellings

## Fixed

- The OmniVoice provider accepted the pronunciation dictionary, previous
  text and next text extensions but never sent them

## Dependencies

- Requires `github.com/plexusone/omnivoice-core` v0.19.0, which adds
  `SynthesisConfig.Pronunciations`
- Indirect dependencies updated
