# v0.14.0 — Reported Sample Rate for Phone-Call Speech

This release fixes the sample rate the OmniVoice TTS provider reports, so
callers that play or convert the audio, such as a phone call bridge, read
the rate of the audio they actually received.

## Highlights

- **Correct sample rate**: `SynthesisResult.SampleRate` is the rate of the
  returned audio. A `mulaw` request returns 8 kHz `ulaw_8000` audio and now
  reports 8000; it reported 44100

## Fixed

- `Synthesize` reported the requested `SampleRate`, or 44100 when none was
  given, instead of the rate of the ElevenLabs format the request was sent
  as. Phone-call formats (`mulaw`, `ulaw`, `alaw`) are always 8 kHz, and an
  explicit name such as `pcm_24000` reports the rate in its name

## Added

- `omnivoice.OutputSampleRate(config)` returns the sample rate of the audio
  ElevenLabs returns for a synthesis config
